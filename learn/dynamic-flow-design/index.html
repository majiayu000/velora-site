作者怎样生成这种图

把上面的 JSON 写进 Markdown 的 flow 代码块即可。作者描述节点和关系，库测量实际网页位置并画线。

字段 内容
title、description 图名和阅读提示
rows 责任分组，每组有 title 与 nodes；同组卡片按可用宽度排列
nodes 每个节点有唯一 id、title，可填 summary 与 detail
edges 用 from、to 关联节点，ID 必须存在
dashed 用虚线表达回路或补充关系，含义由图例说明
route 指定 left 或 right 沿图边缘绕行；省略时按卡片位置生成直线或曲线
label 简短的连线文字，适合放在留有空间的连接上
paths 可选的流程名称与节点列表；选择后突出这些节点之间的关系

节点说明是纯文字。把详细证据与代码出处放进图后的正文，图负责让读者先理解责任与流向。

连线怎样跟上排版

  1. HTML 卡片由 CSS Grid 排列，卡片高度随文字自然变化。
  2. 浏览器测量每张卡片的边界，把位置换算到 SVG 坐标。
  3. 同行从两张卡片相邻边缘连接；跨行用曲线；显式绕行沿左右空白通道走。
  4. ResizeObserver 观察画布和卡片尺寸。字体就绪、缩放、展开或收起也会触发重画。

缩放时整张画布与卡片文字一起缩放，连线坐标按同一比例换算。适应宽度时卡片重新排版；展开阅读时提供更宽的画布，可以在图内滚动。

与固定 SVG 的区别

svg 图块适合明确设计好坐标的图；flow 图块适合正文卡片需要自然换行、跟随网页宽度排版的关系图。两者共享阅读工具，都保存在 Markdown 中。

这个组件使用节点边界与指定的左右通道画线，没有通用自动避障引擎。复杂的跨层关系需要作者安排好分组并指定绕行；特别密集的图应拆成概览与细节图。流程切换是关系过滤，不执行图中的任务。

设计参考：本机 AI/tools/cli/docs/reports/higgsfield-atlas-architecture-20260929.html 的 Grid 卡片、drawEdges、ResizeObserver 和节点详情。当前实现见 learn/src/flowcharts.ts、learn/src/diagrams.ts 与 learn/src/markdown-renderer.ts。
