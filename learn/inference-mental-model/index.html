推理性能心智模型

从 Prefill、Decode、KV Cache 和四类性能指标理解瓶颈

直接答案

LLM 推理优化的核心，是让计算、显存或内存、通信和排队更好地配合。第一步不是选择 CPU 还是 GPU，而是先判断请求卡在 Prefill、Decode、KV Cache、通信还是调度。

必备概念

一次典型文本生成包含两个阶段：

阶段 做什么 常见瓶颈 最相关指标
Prefill 并行处理全部输入 Token，并生成初始 KV Cache 大矩阵计算、长 Prompt、排队 TTFT
Decode 读取已有 KV Cache，每一步生成一个或少量 Token 权重与 KV 读取、同步、调度间隙 TPOT、ITL

TensorRT-LLM 的阶段分离文档也把 context/prefill 和 generation/decode 视为计算特性不同的两个阶段，并指出两者共享 GPU 时会互相干扰。TensorRT-LLM Disaggregated Serving

KV Cache 是什么

Transformer 在生成后续 Token 时需要过去 Token 的 Key/Value 状态。KV Cache 保存这些中间结果，避免每次从头计算整段历史。

它带来一个关键交换：计算量下降，但每个并发请求都会占用更多内存或显存。上下文越长、并发越高，KV Cache 越可能先于算力成为容量上限。TensorRT-LLM 使用分块池管理 KV Cache，并支持跨请求复用、卸载和淘汰策略。TensorRT-LLM KV Cache System

四类不能混为一谈的指标

指标 用户感受 容易被什么影响
TTFT 等多久看到第一个字 排队、Prompt 长度、Prefill、前缀缓存
TPOT / ITL 后续文字出来得是否流畅 Decode、批次大小、通信、抢占
Throughput 集群每秒处理多少 Token 批处理、并发、量化、设备数量
P99 高峰期最慢的请求有多慢 排队、长短请求混跑、缓存不足、故障

只汇报平均吞吐会掩盖交互体验。vLLM 的持续基准也同时观察吞吐、TTFT、TPOT 和满足延迟约束时的最大并发。vLLM Performance Dashboard

从请求到输出的状态所有权

API 层
  拥有：请求身份、截止时间、取消信号
  ↓
路由与准入层
  拥有：目标副本、排队或拒绝决定
  ↓
调度器
  拥有：本轮运行哪些序列、分配多少 Token 预算
  ↓
KV Cache 管理器
  拥有：缓存块、引用、淘汰和容量
  ↓
模型执行器
  拥有：权重、算子、设备流和分布式通信
  ↓
流式响应与观测
  拥有：Token 输出、TTFT/TPOT、错误分类

这条所有权边界很重要。例如 KV Cache 不足时，调度器必须明确选择排队、抢占或拒绝，不能偷偷丢弃上下文后继续生成。

优化手段到底改了哪里

优化 主要作用位置 首要目标 典型代价
连续批处理 调度器 提高设备利用率和吞吐 排队或批次过大可能增加延迟
Paged KV Cache 缓存管理 减少碎片，提高并发容量 元数据和调度更复杂
Prefix Cache Prefill/KV 降低重复前缀的 TTFT 需要缓存感知路由和淘汰
Chunked Prefill 调度器/Prefill 避免长 Prompt 阻塞 Decode 参数需要按流量调节
量化 权重、激活或 KV 降低容量和带宽压力 精度、内核、硬件兼容风险
数据并行 路由/副本 提高集群总吞吐 权重和缓存重复占用
张量并行 模型执行 让模型跨设备，缩短单步计算 每层需要高频通信
投机解码 Decode 减少目标模型串行步数 draft 成本和接受率不确定

一个实用判断顺序

  1. 模型和目标上下文能否放进单个设备或单个 NUMA 实例？
  2. 单请求延迟在低并发时是否达标？
  3. 增加并发后，是算力、缓存容量还是排队先饱和？
  4. 优化后 TTFT、TPOT、P99 和错误率分别怎样变化？
  5. 每百万 Token 成本是否真的下降？

如果第一步都没有测量，就直接上多节点，通常只是在把未知瓶颈复制到更多机器。

失败和边界行为

  • 输入超过支持的上下文长度，应返回明确错误。
  • KV Cache 或设备内存不足，应排队、抢占或拒绝，并暴露原因。
  • 某种量化或内核不兼容，应启动失败或明确拒绝配置，不能静默退回一个性能完全不同的路径。
  • 分布式 rank 丢失时，不能把残缺结果作为正常回答返回。
  • 指标缺失时，基准结果应标为无效，不能用平均值代替 P99。

自己动手观察

保持模型和并发不变，只把输入长度从 128 Token 增加到 4096 Token：

  • TTFT 应发生什么变化？
  • TPOT 是否以同样幅度变化？
  • 峰值 KV Cache 为什么会上升？

然后保持输入长度不变，提高并发。观察最先恶化的是 TTFT、TPOT、吞吐还是错误率。

小测验

一个优化让吞吐提高 30%，但 P99 TTFT 从 1 秒变成 8 秒。它是否更好？

答案取决于服务 SLO。离线批处理可能接受，交互式聊天通常不能接受。这也是后续所有章节的判断基线。
