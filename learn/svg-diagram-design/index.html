把流程讲清楚：SVG 图与节点说明

先按「谁负责什么」分层，再画关系。SVG 不只是图片格式：矩形是节点，path 是连线，marker 是箭头；它们一起构成可缩放的流程图。本页的图是 Learn Workbench 教学示例，不表示任何外部产品的后端架构。

需要随卡片排版重画连接时，查看 动态连接的交互流程图。

一张图讲一个问题

这张图回答：Agent 的建议怎样成为读者看到的教程？上排是提出建议，下排是审核后的文档流。点击节点看输入、输出和边界，相关连线会突出显示。适应宽度看全局，展开阅读看细节。

代码依据：learn/src/MarkdownView.tsx、learn/src/markdown-renderer.ts、learn/src/diagrams.ts、learn/src/ArtifactPanel.tsx、src/adapters/runtime-codex/codex-runtime.ts。本图简化了错误与冲突分支；分析完整保存协议时应另画专门流程，不能把成功路径当成所有情形。

Agent 怎样生成这样的图

使用标准 Markdown 的 svg 代码块，内容是完整 SVG；需要有效的 viewBox="0 0 宽 高"。不用 MDX、JavaScript 或单独图表文件。复制本页图块就是可编辑示例。

元素 用途 写法
根 title、desc 图名、图例与阅读提示 图块顶部与底部显示
g data-node="id" 可点击、可用键盘选择的节点 内放 title 和 desc，描述责任、输入输出、边界
path data-from="id" data-to="id" 节点之间的关系 点击节点时突出关联路径
defs / marker 箭头 marker-end="url(#arrow)"；渲染器自动隔离各图的 ID
M / H / V / C 起点、水平、垂直、曲线 SVG 原生路径指令；布局和绕行由作者安排
stroke-dasharray 回路、参考关系等 先在图例说明含义，不能随意混用

建议先写清楚节点职责和关系，再排版：主流程朝一个方向；边线从节点边缘出发，别穿过文字；跨层路径走留出的空白；回流绕外边缘；路径放在节点之前，线被节点遮住时不会压住文字。节点标题保持一行，细节放在 desc 和图后正文。

当前提供 SVG 渲染与阅读交互，没有自动布局或自动避障。节点坐标与连线坐标需要一起更新。此前本机的 Higgsfield–Atlas 页面采用 HTML 节点加 SVG 覆盖层，在 drawEdges() 中按节点的位置计算路径；那种响应式连线现在由 flow 图块提供；固定 svg 图块仍使用作者安排的坐标。本页选择固定坐标以保持 Markdown 可移植，适应宽度与展开阅读用于不同屏幕。

显示与边界

  • 阅读页、编辑预览、Agent 回答和只读站使用同一图块。放大后在图内滚动；展开阅读可按 Esc 收起；节点支持 Tab、Enter 和空格。
  • 没有 data-node 的 SVG 也能作为普通矢量图显示；没有 desc 时显示节点标题。
  • SVG 的脚本、事件处理器、样式标签、内嵌网页、图片和外部引用不进入图块。颜色与线型使用 SVG 属性，例如 fill、stroke，不要依赖 <style>。
  • 格式不完整或 viewBox 无效时保留源代码，并显示原因。图太大时优先拆成概览和细节图，而不是缩到读者看不清。
