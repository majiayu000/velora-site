Evidence: verified for metric definitions and framework benchmarking practice; all target values are unknown until the user supplies an SLO.

直接答案

一次可信的推理优化实验必须固定模型、硬件、请求分布和质量要求，每轮只改变一个主要变量，并同时报告延迟、吞吐、错误、资源和成本。没有对照组或没有 P99 的结果，不能支持集群配置决策。

先写清楚服务目标

不同产品追求的目标不同：

场景 首要指标 可接受交换
交互聊天 TTFT、TPOT、P99 可以牺牲部分峰值吞吐
批量摘要 总吞吐、成本 可以等待更大的批次
代码补全 极低 TPOT 和稳定尾延迟 通常不适合长队列
长文档问答 长 Prompt TTFT、KV 容量 可能需要缓存或阶段分离

在实验前写出硬门槛，例如：

P99 TTFT <= 2 s
P99 TPOT <= 80 ms
错误率 < 0.1%
上下文不得截断
满足以上条件时，最大化输出 tokens/s/GPU

这些数字只是格式示例，不是当前项目已经确定的 SLO。

固定工作负载

至少记录：

  • 模型名称、版本、精度和量化方式。
  • 推理框架及版本。
  • CPU/GPU 型号、数量、NUMA 或 GPU 互联拓扑。
  • 节点间网络类型。
  • 输入长度和输出长度分布，不只写平均值。
  • 并发模型：固定并发、固定请求率，还是突发流量。
  • Prompt 是否包含可重复前缀。
  • 采样参数和随机种子。
  • 预热次数、测量时长和重复次数。

如果这些字段变化，两个结果不能直接比较。

最小指标集

用户体验

  • TTFT：请求到第一个 Token。
  • TPOT/ITL：首 Token 之后的生成间隔。
  • E2E latency：整个请求完成时间。
  • P50、P95、P99，而不只是平均值。

容量与效率

  • 输入、输出和总 tokens/s。
  • 成功请求数与最大稳定并发。
  • GPU 显存或 CPU 内存峰值。
  • KV Cache 使用率、命中率、抢占或淘汰数。
  • GPU 利用率、计算时间和通信时间。
  • 每百万输入/输出 Token 成本。

正确性

  • 输出是否完整，是否发生上下文截断。
  • 量化前后任务质量是否越过允许阈值。
  • 请求失败、超时、取消是否被正确分类。
  • 不支持的内核是否发生 fallback。

推荐实验矩阵

CPU 路径

轮次 唯一主要变化 要回答的问题
C0 未绑定基线 当前瓶颈和波动多大？
C1 NUMA 与核心绑定 远端内存访问是否下降？
C2 调整线程预算 是否消除超卖和忙等？
C3 量化 内存、吞吐和质量怎样变化？
C4 连续批处理 吞吐收益是否破坏 TTFT/P99？
C5 增加请求级副本 扩容是否接近线性？

GPU 路径

轮次 唯一主要变化 要回答的问题
G0 单卡基线 单请求与饱和点在哪里？
G1 连续批处理 设备空洞是否减少？
G2 Prefix Cache 真实前缀流量命中多少？
G3 量化 容量和内核收益是否兑现？
G4 DP 副本 总吞吐和尾延迟如何扩展？
G5 TP/PP/EP 通信成本是否低于计算收益？
G6 阶段分离 TTFT/TPOT 收益是否覆盖 KV 传输？

不要在 G1 同时打开量化、Prefix Cache 和 TP。即使结果变快，也无法知道哪项有效、哪项有害。

判定结果是否有效

配置可启动
  -> 预热完成
  -> 固定负载运行足够时长
  -> 无关键指标缺失
  -> 错误率和正确性通过
  -> 多次重复结果稳定
  -> 才比较性能和成本

以下情况应该把整轮标为无效：

  • 指标采集器中途退出。
  • 一部分请求被静默截断或丢弃。
  • 量化内核不支持，运行时回退但未单独标记。
  • 某个分布式 rank 反复重启。
  • 两轮使用不同模型版本或不同长度分布。
  • 只保留最好的一次结果。

从现象反推下一步

现象 优先调查
低并发 TTFT 已经很高 Prefill、模型加载/冷启动、Tokenization
并发上升后 TTFT 急剧恶化 排队、批次预算、准入控制
TPOT 高但 GPU 利用率低 调度间隙、通信、CPU 前端、同步
GPU OOM 但算力未饱和 KV Cache、上下文、碎片、容量设置
CPU 利用率高但吞吐低 内存带宽、NUMA、线程超卖、fallback
DP 扩容不线性 路由、前端瓶颈、共享存储或网络
TP 增卡反而变慢 All-Reduce、拓扑、批次太小
Prefix Cache 命中很低 路由错位、前缀不稳定、淘汰策略

完成标准

当你能根据同一组负载解释以下问题，这轮学习才算闭环：

  1. 当前系统的主要瓶颈是什么？
  2. 优化改变了哪段执行链？
  3. 哪个指标改善，哪个指标退化？
  4. 收益来自计算、内存、通信还是排队？
  5. 在什么负载或硬件边界下结论会失效？

下一步最有价值的是选一个真实推理仓库和一套实际硬件，把这份模板变成第一份可复现报告。
